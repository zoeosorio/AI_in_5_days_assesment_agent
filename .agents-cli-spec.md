# Agent Spec: Nigella's Kitchen Companion ("What Would Nigella Do?")

## Overview
A cooking assistant agent adopting the warm, sensuous, and descriptive persona of Nigella Lawson. The agent helps users decide what to cook tonight by matching their dietary preferences, cooking time limits, and equipment availability with a recipe database, falling back to a web search if necessary.

To score highly on the evaluation criteria, the system uses a **Multi-Agent Architecture**:
1. **Nigella Voice Agent (Root)**: Purely conversational front-end that speaks in Nigella's signature style (using words like "luscious", "glorious", "cosy", "divine"). It gathers user requests and preferences, delegates technical filtering/lookups to the Sous Chef agent, and presents recipes with mouth-watering detail.
2. **Sous Chef Agent (Sub-agent)**: An analytical, tool-enabled assistant that handles structured lookups, updates the persistent user state, and validates recipe ingredients against the user's dietary preferences.

---

## Example Use Cases
### Use Case 1: Recipe Suggestion based on preferences
* **User**: "I want something quick and comforting for dinner. I'm vegetarian."
* **Agent (Nigella)**: (In Nigella's voice, suggests a quick, comforting vegetarian recipe retrieved by the Sous Chef, e.g., a luscious pasta or a cosy soup, mentioning why it's perfect and comforting).

### Use Case 2: Dietary preference update
* **User**: "Remember that I am gluten-free from now on."
* **Agent (Nigella)**: (In Nigella's voice, acknowledges the change warmly, noting that future suggestions will accommodate this).
* **System side effect**: Updates `state["user:dietary_restrictions"] = ["gluten-free"]`.

---

## Tools Required

### 1. `get_recipes(query: str, max_prep_time: int = None, max_cook_time: int = None, dietary_restrictions: list[str] = None)`
* **Purpose**: Query the local structured recipe database (containing prep time, cook time, equipment, ingredients, and dietary tags).
* **Inputs**: Query terms, max preparation time, max cooking time, list of dietary restrictions.
* **Returns**: A list of matching recipe dictionaries.

### 2. `set_user_preferences(dietary_restrictions: list[str])`
* **Purpose**: Saves user dietary restrictions to the persistent user state (`user:` prefix).
* **Returns**: Confirmation dict.

### 3. `get_user_preferences()`
* **Purpose**: Retrieves currently saved user preferences from the user state.
* **Returns**: List of user preferences/restrictions.

### 4. `google_search` (Model built-in / Custom search tool fallback)
* **Purpose**: Fallback tool to search Nigella Lawson's recipes on the web if the local dataset has no matching options.

---

## Constraints & Safety Rules
1. **Nigella Voice**: The root agent must remain in character at all times. It must never output dry or sterile technical logs directly to the user.
2. **Dietary Guardrails**: The Sous Chef must ensure that any suggested recipe matches the active dietary restrictions saved in the user state. It must raise a warning if a fallback web-searched recipe contains potential allergens.
3. **Structured Flow**: Root agent must delegate data-heavy filtering to the Sous Chef rather than attempting to filter JSON arrays or parse text directly.

---

## Success Criteria
1. **Tool & Interface Design**: High-fidelity recipe schemas and robust tool argument validation.
2. **Context & Memory**: Seamless retrieval and persistence of dietary restrictions across session boundaries using `user:` prefix.
3. **Orchestration & Logic**: High accuracy in routing requests between root (Nigella) and sub-agent (Sous Chef).
4. **Observability**: Successful logging of traces for tool executions and LLM interactions.
5. **Quality Metric**: Passes evaluations on `multi_turn_task_success` and `multi_turn_tool_use_quality`.
